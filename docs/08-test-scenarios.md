## 1. 수요일 저녁 MVP 완료 기준 (9/30)

- [ ] 고정 샘플로 화면 1 → 7이 끊김 없이 완주한다 (마이크 녹음 사용)
- [ ] 서류 4종에서 요구사항·주장·검증 포인트가 실제 LLM으로 생성된다

## 4. 회귀 실행 순서 (제안)

1. 목요일 오전: 섹션 3 자동 테스트 전부, 섹션 2 Must 전체 수동 실행

## 5. 발표 리허설·데모 fallback 체크리스트

리허설: 10/2(금) 오전, 발표는 16시.

### 발표 전날(10/1) 밤까지

- [ ] 시연 영상(화면 1→7 완주)이 발표 PC에서 재생된다
- [ ] PPT 최종본과 영상이 발표 PC에 저장돼 있다
- [ ] 데모용 고정 서류 4종, 예상 답변 대본이 준비돼 있다
- [ ] `.env`의 키가 발표 환경에서 유효하다 (키를 화면에 노출하지 않는다)
- [ ] 마이크·카메라 권한이 발표 브라우저에서 허용돼 있다
- [ ] 터널 HTTPS 주소로 접속해 마이크·카메라 권한이 뜨고 화면 1→7이 완주된다 (원격 접속이 필요한 경우)
- [ ] 발표 PC에서 `docker compose up`으로 로컬(`localhost`) 실행이 되는 fallback을 확인했다

### 리허설 (10/2 오전)

- [ ] 발표 시간 안에 전체를 한 번 완주했다
- [ ] 라이브 데모를 한 번 완주했다 (분석 20~40초, 최대 60초 대기 시간의 멘트도 정했다)
- [ ] 각 담당이 자기 화면 설명을 말했다
- [ ] 예상 질문 점검 (합격 가능성 표현 금지, 카메라 지표는 점수에 반영되지 않는 참고값, 음성은 변환 후 삭제, 영상은 서버로 가지 않음)
- [ ] 기능 추가 없이 버그 수정만 했다

### 데모 fallback

| 상황 | 대응 |
|---|---|
| 마이크·카메라 권한 실패 | 시연 영상으로 전환. 권한 재확인을 먼저 시도 |
| 서버·LLM 응답 지연·실패 (분석 60초 초과) | 「다시 시도」 1회, 안 되면 시연 영상 |

| TTS 실패 | 질문 텍스트만 보여주고 진행 |
| 진행 시간 부족 | [docs/06-wbs-schedule.md](06-wbs-schedule.md)의 축소 순서에 따라 시연 범위를 줄이고 영상으로 보완 |
